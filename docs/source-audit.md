# 元ツールの移植判断

対象: https://github.com/humandoll26/receipt-pdf-app

確認コミット: `1091177b92063f1c16eb836f9e9c06bc2e5a94b8`

今回は主要JavaScript・依存関係・保存方式を読み取り確認した実装前調査。網羅的なセキュリティ監査や法令適合の認定ではない。元リポジトリ・公開ツールを変更していない。

| 対象 | 判断 | 新アプリでの扱い |
| --- | --- | --- |
| PDF生成 | 抽象化・改修 | pdf-lib/fontkitの構成を採用し、明細・複数税率・複数ページを新実装 |
| 日本語フォント | 除外 | YuMincho.ttfの利用条件は確認できていない。SIL OFLのNoto Sans JPへ置換 |
| 金額表示・折り返し | 流用可能な考え方 | TypeScriptで新実装。文言を切り捨てず複数ページへ送る |
| 税計算 | 再実装 | 元は金額・税率が各1つ。内税で税抜額をfloorして差を税額としている。新アプリは税率別に合算した税額を指定方式で一度丸める |
| IndexedDB/Dexie | 除外 | 業務記録と原本はNotion。採番・再試行のみ永続ローカルジャーナル |
| localStorage発行者設定 | 除外 | Notionの発行者設定。発行時はスナップショット化 |
| 年月付き採番 | 改修 | 表記を継承し、サーバーの直列処理とSQLiteの予約・UNIQUE制約で保護 |
| 履歴編集・削除 | 除外 | 元は再出力時にも上書き可能。新アプリは下書きのみ編集可能。確定済みは原本取得・取消・訂正発行 |
| CDN依存 | 改修 | npmの固定バージョン・lockfileを使用。PDFフォントは同梱 |
| JSONバックアップ | 別実装が必要 | 初版はNotion添付JSONと原本を保持。自動一括バックアップ/復元のUIは未実装 |

元ツールは記録保存後にPDF生成するため、PDF生成失敗でも記録が残る。新アプリは発行処理中と発行済みを分け、原本の保存・読み戻し確認後に確定する。

元ソースで確認した主な外部ライブラリはpdf-lib 1.17.1、fontkit 1.1.1、Dexie 4.0.8。今回Dexieは採用していない。元のLICENSEファイルは確認できていないため、元ソース全体をコピーせず実装を作成した。

Noto Sans JPの取得元: https://github.com/google/fonts/tree/main/ofl/notosansjp

フォントライセンス: `assets/fonts/OFL.txt`。PDFではサブセット埋め込みし、Notion無料プランの1ファイル5MiB以内を確認する。
